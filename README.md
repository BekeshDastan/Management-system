# Diet

Личное Android-приложение для питания, веса, сна и прогресса.

**Состояние:** прототип v0.4 принят пользователем 15 ноября 2026 года. Подготовлены ТЗ v1.0, правила данных, каталог приёмки и пошаговый план. Новым поручением разрешена Android-реализация; исходники и APK проходят сборочные/runtime проверки. Готовность фиксируется по фактическому [отчёту сборки](docs/build-validation.md).

## Что войдёт в приложение

Офлайн без регистрации и рекламы: профиль, собственные продукты/рецепты, питание с историей/копированием, ручные цели по датам, вес/сон, календарь, сворачиваемые отчёты и графики, игровые названия/уровни, фото/заметки/настроение и фотолента, поиск, шаблоны, план питания, быстрые порции, настраиваемая главная/оформление и реальные напоминания.

Полный релиз сохраняет весь принятый объём. Раннее устанавливаемое ядро — только промежуточная проверка. Резервные копии и восстановление исключены пользователем. Аккаунт/синхронизация и расчётные рекомендации отложены; Kotlin/Compose/Room выбраны пользователем; точные плановые версии закреплены отдельно, совместная сборка ещё не проверена.

Документальный этап 0 продолжается: выбраны Kotlin + Jetpack Compose + Room и минимум Android 10 / API 29. Профиль S23+ получен со слов пользователя, у близких самый старый названный Android — 14. Выбраны compile/target 37 и точная плановая конфигурация, подготовлена предметная матрица. Ожидаются модель близких и дополнительные физические сведения; разрешение графа/сборка/испытания не выполнялись. TECH-001/002 отделяют готовые документальные решения от этих оставшихся проверок. Документально завершены выбор точности/пределы TECH-003 и схема/миграции/черновики TECH-004; исполнительная проверка ядра/Room остаётся будущей. Документально определены TECH-005/006: обработка/владение фото, memory/disk бюджеты и политика исключения системного копирования; фактические файлы, decoder и transport-проверки ещё не создавались. TECH-007/008 и общие показатели TECH-009 остаются открытыми. Установки и код не выполняются.

## Порядок работы

1. Использовать ТЗ, правила данных и сценарии как единую базу, каталог проверок — как ожидаемый результат.
2. До функций закрыть документальные решения зависимых этапов. После отдельного разрешения на код первым шагом проверить минимальную сборочную основу по выбранной конфигурации; физические сведения уточнить до испытаний.
3. После отдельного запроса пользователя на реализацию выполнять план небольшими законченными сценариями. Сейчас разрешены только документы.
4. Каждую правку проверять, документировать, отдельно коммитить/push и сверять remote SHA. Локальный файл не считать опубликованным изменением.

## Посмотреть макет
