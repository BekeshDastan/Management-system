## 2026-11-14 — диагностика различий доступа к Git

- Пользователь уточнил требование: коммиты должен делать агент; ручной запуск пользователем не является решением рабочего процесса.
- Проверены контекст процесса, атрибуты и ACL каталога .git, наличие index.lock, состояние репозитория и отдельные параметры локальной конфигурации Codex. Учётные данные и секреты не читались.
- Файл .git/index.lock отсутствует. Это ошибка создания lock-файла, а не зависший lock, который нужно удалять.
- Процесс агента имеет низкий уровень целостности Windows. В действующей политике задачи .git явно доступна только для чтения; запросы расширения sandbox-доступа отключены. Обычный PowerShell пользователя не работает под этой политикой.
- В локальной конфигурации указан windows.sandbox = elevated. Это выбор механизма изоляции, а не предоставление агенту неограниченных прав; действующая политика задачи продолжает ограничивать запись.
- Документация OpenAI подтверждает защиту .git в workspace-write и различие между ограничениями sandbox и одобрениями действий: https://learn.chatgpt.com/docs/agent-approvals-security и https://learn.chatgpt.com/docs/sandboxing.
- Исправление должно выполняться через поддерживаемое управление разрешениями задачи: разрешить одобрение нужных Git-операций, сохранив границу проекта. Агент не менял ACL, настройки защиты или собственные разрешения и не пытался обойти ограничения другой оболочкой.
- Подключение GitHub не подтвердило возможность записи через интеграцию; предыдущая рекомендация установить расширение не решила проблему локального Git. Справка: https://help.openai.com/en/articles/11145903-codex-cli-getting-started.
- Состояние публикации не изменилось: новые документы и этот журнал остаются локальными; новый коммит в рамках диагностики не создавался. Следующий шаг — включить поддерживаемый режим одобрения и проверить git add, commit и push самим агентом.
