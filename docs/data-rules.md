# Diet — правила данных и вычислений v1.0

Дата: 15 ноября 2026 года. Основание — принятый прототип v0.4 и решения D-001–007. Это контракт поведения; фактическая реализация/проверки перечислены в [implementation-coverage.md](implementation-coverage.md). Типы/точность/пределы выбраны в [numeric-contract.md](numeric-contract.md); логическая схема и протоколы сохранения выбраны в [storage-model.md](storage-model.md), [migrations.md](migrations.md) и [drafts.md](drafts.md). Room schema1 реализована; будущая миграция1→2 и физическая приёмка остаются открытыми.

## 1. Логические данные

| Объект | Минимально необходимые сведения и инвариант |
|---|---|
| Профиль | Необязательные имя, возраст, рост, исходный вес, направление. Изменение не создаёт измерение или цель. |
| Приём пищи | Постоянный ID, текущее имя, порядок, признак архива. ID не зависит от позиции/имени. Хотя бы один активный приём. |
| Продукт | ID, имя, база 100 г / 100 мл / 1 именованная порция, четыре значения КБЖУ, избранное и категория. |
| Рецепт | ID, имя, глубокие снимки ингредиентов и их количества, отдельно выход готового блюда в граммах. Вложенных рецептов нет. |
| Запись еды | Собственный ID, календарная дата, ID приёма, имя/база/единица/КБЖУ снимка, количество, рассчитанные значения, необязательная связь с источником. Быстрый ввод хранит КБЖУ всей порции. |
| Полнота питания | Отдельное подтверждение для даты, не выводится из достижения цели или наличия измерений. |
| Цель | Дата начала и четыре значения. На одну дату начала — одна действующая версия; явная правка подтверждается. |
| Вес / сон | Независимые записи с уникальной календарной датой для каждого показателя. Вес — сотые кг; сон — целые минуты. Отсутствие записи отлично от нуля сна. |
| Личные моменты | На дату: необязательное настроение, заметка, список фото. У фото собственный постоянный ID, локальный ресурс, подпись и необязательный ID приёма. |
| Шаблон | ID, имя и глубокие снимки строк еды с количествами, независимо от дневника/каталога. |
| План | ID, имя, плановая дата/приём, собственные снимки строк. История переносов содержит фактическую дату/приём и ID созданных записей. |
| Настройки | Тема/шрифт, акцент/обложка, видимость/порядок блоков, независимые игровые переключатели, быстрые порции, напоминания и предпочтения отчёта. |
| Черновик и операция | Отдельные от сохранённых данных поля/контекст. У подтверждаемого сохранения есть защита от непреднамеренного повторного применения. |

Возраст профиля — положительное целое или пусто; рост в см и исходный вес в кг — положительные числа или пусто. Имя профиля необязательно. Названия приёмов непустые и уникальные после обрезки пробелов, без учёта регистра, включая архив; последний активный приём нельзя архивировать.

Удаление продукта, рецепта, шаблона или плана не удаляет чужие снимки и уже внесённую еду. Приём архивируется с сохранением истории. Переименование приёма меняет подпись его ID, а не переносит записи; имя продукта в старой еде остаётся именем снимка. При удалении фактической записи журнал переносов плана сохраняется как факт прошлой операции, а не гарантия существования записи сейчас.

## 2. Числа и ввод

- КБЖУ и количество принимают десятичный ввод с запятой или точкой. Все четыре КБЖУ обязательны; явный 0 допустим, пустое и неизвестное не равны 0. Количество положительно, калорийная ручная цель строго положительна, её БЖУ неотрицательны.
- Вес строго больше 0, максимум два десятичных знака. Лишние разряды отклоняются без скрытого округления. Профильный исходный вес не связан с датой измерения.
- Сон: оба целочисленных поля обязательны; часы неотрицательны, минуты 0–59. Итог в минутах. 0 ч 0 мин сохраняется только после подтверждения. Дополнительные эпизоды пользователь суммирует вручную на дату пробуждения.
- Нет скрытого преобразования граммов в миллилитры, штук в граммы или состава в фактический выход. Минуты 60 не превращаются молча в 1 час.
- Расчёты выполняются по исходной десятичной точности; округление применяется к представлению результата, не к каждой карточке до суммирования. Для неотрицательных результатов половина округляется вверх: питание до 0,1; средний вес до 0,01 кг; средний сон до минуты. Исходное измерение не изменяется округлением среднего.
- NaN/Infinity, переполнение и непредставимые итоги дают явную ошибку; они не становятся пропуском или нулём. Допустимые разряды/диапазоны КБЖУ, количества, выхода, профиля и длительности, точные рациональные снимки и бюджеты агрегата зафиксированы в [числовом контракте](numeric-contract.md). Это инженерные пределы, не медицинские ограничения. JavaScript MAX_SAFE_INTEGER макета не является пределом Android. Количество/выход отображаются с достаточной выбранной точностью, а не общей точностью нутриентов: положительное допустимое количество не показывается 0, соседние допустимые значения различимы.

### 2.1. Порции и рецепты

Для каждого компонента КБЖУ: `значение порции = значение базы × количество / размер базы`.

Для рецепта сначала сложить неокруглённые значения порций ингредиентов. Значение на 100 г готового блюда равно `итог × 100 / выход`; съеденная порция равна `итог × съеденные граммы / выход`. Имя продукта/рецепта/именованной порции непустое; рецепт содержит минимум один допустимый ингредиент. Выход обязателен и положителен, сумма масс сырья не подставляется вместо него. Ингредиенты используют снимки, включая смешанные исходные единицы; плотность не придумывается. Нулевая масса ингредиента недопустима, нулевое КБЖУ само по себе не ошибка.

Правка количества старой еды пересчитывает её по сохранённому снимку. Замена источника — отдельное явное действие с предпросмотром и сохранением; отмена не меняет прошлое. Обновление снимка ингредиента рецепта требует явного действия и видимого пересчёта; уже съеденное остаётся прежним.

## 3. Даты и полнота

Дата дневника — локальная календарная дата, не мгновение UTC. Историческая дата не меняется при смене часового пояса. Для новых фактических записей выбирается сегодня или прошлое; план допускает до текущей даты +90 календарных дней, цель может начинаться в будущем. Перезагрузка не фиксирует «сегодня» на демонстрационном 14 ноября: приложение использует реальные дату/часовой пояс устройства.

Форма показывает и сохраняет выбранную дату даже после полуночи. При изменении суток нельзя молча переносить еду/измерение. Для первого запуска с ещё не подтверждённой датой начала цели переход суток требует явного выбора даты перед применением; прежняя дата не получает цель автоматически. Удаление/исправление никогда не выбирает новую дату вместо сохранённой. Смена часов/зоны не удаляет и не скрывает уже существовавшие записи; поведение создания новых записей при неверных часах проверяется отдельно.

| Строки еды | Подтверждение | Состояние |
|---|---|---|
| Нет | Нет | Нет записей |
| Есть | Нет | Частично |
| Есть | Есть | День заполнен |
| Нет | Есть, явно подтверждено отсутствие еды | Заполненный нулевой день |

Добавление/исправление/перенос строк в заполненный день сохраняет подтверждение. Удаление последней строки предупреждает и снимает его; нулевой день не возникает побочным эффектом удаления. Ручное снятие отметки у нулевого дня возвращает «Нет записей». Вес, сон, настроение, фото, шаблоны и планы полноту питания не меняют. Отмена/сбой сохраняют и строки, и прежний статус.

## 4. Выборки отчётов

- Календарь месяца начинается с понедельника. Период включителен с обеих сторон. M — число календарных дат. 7 дней — конечная дата и шесть предыдущих; 30/90 — скользящие периоды обзора. Подробные графики: 7 дней, с начала месяца/года и произвольный диапазон.
- Вес и сон усредняются независимо по имеющимся записям с собственными N/M. Подтверждённый нулевой сон входит. N=0 даёт прочерк, а не 0.
- Доменная выборка завершённых дней сохраняет N, включая явно подтверждённый нулевой день; partial в неё не входит. Отдельный обзор1.2 показывает все фактически внесённые complete+partial значения без переключателя. Сумма = точная completeMean×N + partialMean×P; среднее обзора = сумма/(N+P). Подпись «Записано … из M дней» указывает эту выборку. Missing не входит и не превращается0; confirmedzero входит один раз. Исходные N/Q не переписываются.
- Цель на дату — последняя по дате начала, не позднее этой даты. Действует до дня перед следующей целью. До первой цели значение отсутствует. Замена занятой даты/прошлого и удаление показывают затронутый период и подтверждение.
- Сравнение питания и цели использует общую выборку Q заполненных дат с действовавшей целью; обе средние берутся по Q. Q может отличаться от N. Удалённая цель возвращает предшествующую либо отсутствие, но не нулевую цель.
- У календарной недели обзора1.2 границы понедельник–воскресенье, текущая обрезана сегодняшним днём; стрелки переходят между календарными неделями. Остальные интервалы переходят по собственной длине с явной нижней границей. Разницы средних не являются медицинским заключением; у каждой стороны своя выборка.
- Цель обзора1.2 усредняется по календарным датам с действовавшей целью (goalDays), отдельно от сравнения Q. Пунктир цели строится по goalMean каждого интервала: соседние одинаковые значения соединяются во всю их ширину, исторические изменения отражаются, даты без цели оставляют пробел. Нынешняя цель не заполняет прошлые даты.
- Пропуск разрывает линию графика, отдельная запись остаётся точкой. Вес допускает явно подписанную ненулевую нижнюю границу; сон/питание начинаются с 0. Точная таблица/дата доступна без опоры только на цвет.
- Частые продукты — частота всех фактических строк периода, включая частичные дни, по сохранённому имени, не рейтинг пользы; выводятся первые пять по числу записей (при равенстве — стабильный порядок имени). Календарь различает питание/вес/сон/моменты; личные моменты могут сделать день видимым как день с записями, не заполняя питание.
- Предел 366 дат графика — ограничение макета. Android должен сохранять всю историю; предельный диапазон одной отрисовки/агрегация выбираются по измерениям производительности и не обрезают хранение.

## 5. Независимость шаблонов, плана и факта

Шаблон копирует только еду, не фото, заметку, настроение или полноту. План принимает продукты/состав шаблона глубокими копиями. Правка источника не меняет шаблон/план, правка шаблона не меняет план, ни одна из них не меняет факт.

Для добавления показываются состав/итог/дата/активный приём, затем подтверждение. Внесение добавляет новые ID к существующим строкам; источник и полнота назначения прежние. Непреднамеренное двойное нажатие не дублирует одну операцию. Намеренное повторное подтверждённое добавление создаёт новый набор; перенос плана повторно явно предупреждается и записывается в историю. Будущая фактическая дата запрещена. Архивный приём источника доступен в истории, для нового назначения выбирается активный приём.

## 6. Личные моменты и настройки

Порядок trim/NFC и подсчёт знаков как code points определены числовым контрактом. Названия продуктов/рецептов/шаблонов/планов/записей еды — до 80 знаков (имя быстрого ввода необязательно), имя профиля/приёма — до 40, именованная единица — до 30. Шаблон/план содержит минимум одну допустимую строку; несколько планов на дату/приём разрешены. Поиск истории: запрос до 100 знаков, выдача порциями по 12 без ограничения общей истории.

База UX: до четырёх JPEG/PNG/WebP на дату, входной файл до 5 × 1024 × 1024 байт; подпись до 80 знаков, заметка до 500; четыре настроения из макета, выбор можно снять. Исторический photoID постоянен даже у одинаковых файлов. Лента читает сохранённые фото, поиск — сохранённую фактическую еду; несохранённое и декоративное в них не попадает. Фильтры и возврат из редактора не подменяют данные.

Приложение должно сохранять выбранное фото локально после перезапуска и показывать ошибку недоступного/повреждённого файла. Для сохранённого фото нужна независимая локальная копия; временный доступ к URI оригинала её не заменяет. Инженерный контракт [обработки](photo-processing.md) выбирает picker/fallback, foreground bounded import, EXIF/нормализацию в оптимизированный JPEG и адаптивный бюджет памяти; [файловый протокол](media-storage.md) — CE noBackup-пути, batch/recovery и очистку. Превью показывает фактическую статичную оптимизированную копию, оригинал не архивируется. Макетный предел стороны 16000 px — защитная проверка демо, не готовый бюджет памяти телефона. Превью/ошибка/отмена не создают полузапись.

В1.2 главная настраивает порядок/видимость трёх блоков (еда, моменты, вес/сон), сохраняя legacy ID прежних настроек. Скрытие не удаляет данные; дата/неделя/серия/сводка/полнота/навигация обязательны, путь восстановления — «Ещё → Настройки». Основной лайм фиксирован, три второстепенных акцента/шесть выбранных обложек и отменяемый черновик сохраняются; большая обложка дневника больше не выводится. Быстрые порции — до пяти различных положительных количеств по ключу ID+база+единица; кнопка меняет только черновик количества. Дефолты: г 100/150/250, мл 100/200/250, именованная база 1 — 1/2/3. Стандартный вид возвращается только с подтверждением.

## 7. Игровые элементы

Текущий уровень определяется числом уникальных дат со статусом «День заполнен» во всей истории. Пороги: 0 — «На старте», 1 — «Первый шаг», 2 — «Дневник в деле», 7 — «В ритме», 14 — «Хранитель привычки», 30 — «Мастер дневника», 60 — «Летописец». Выбирается наибольший достигнутый порог. Пропуск не сбрасывает историю; снятие полноты может уменьшить текущий уровень без наказания. Отдельные очки не вводятся. Новая серия1.2 считает подряд даты с фактической едой либо явным подтверждением0, независимо от уровня: сегодня без записи допускает начало вчера, затем первый пропуск завершает счёт. Вес/сон/фото не дают день серии; пропуски не удаляют ранее заполненные даты и не сопровождаются штрафом. Галочки недельной полосы показывают именно полноту, поэтому частичный день может дать серию без галочки.

| Вес, кг | Название |
|---|---|
| 0 < x <60 | Искра |
| 60 ≤ x <70 | Вихрь |
| 70 ≤ x <80 | Метеор |
| 80 ≤ x <90 | Шторм |
| 90 ≤ x ≤95 | Машина |
| 95 < x <100 (при точности 0,01) | Титан |
| x ≥100 | Богатырь |

Сон: 1–359 минут — «Короткий привал», 360–479 — «Ловец снов», 480–599 — «Соня», от 600 — «Хранитель подушки»; для отсутствия/0 имени нет. Названия не сравнивают здоровье и не поощряют изменение величин. Два независимых переключателя скрывают названия и уровни без удаления истории; начальное включение соответствует принятому макету. Измерения, КБЖУ, фото и число кликов баллы не дают.

## 8. Сохранение и ошибки

Обновление данных/полноты/истории переноса — единая подтверждаемая операция. При ошибке остаются прежние сохранённые данные и редактируемый черновик; успех показан только после надёжного сохранения. Повтор после ошибки выполняется один раз. Постоянные raw-черновики/checkpoints, receipt-first и конфликты версий определены в [drafts.md](drafts.md); схема/владение — в [storage-model.md](storage-model.md), обновления — в [migrations.md](migrations.md). Обновление приложения требует проверенной миграции; уничтожение локальной базы как fallback не считается успешным обновлением.

Фотофайлы и БД требуют согласованной стратегии: подготовка и проверка ресурса, запись ссылки, уборка неподтверждённых файлов, восстановление согласованности после прерывания. Выбранный протокол публикует durable master до draft-ссылок/факта, отменяет весь неполный batch и защищает GC через владельцев/read-leases/tombstone; обычная SQL-транзакция не атомарна для файла и БД одновременно. Системные cloud/D2D-исключения имеют отдельную [политику](system-backup-policy.md) и будущие BP-проверки; функция резервных копий/восстановления не входит в продукт. В UI-state хранятся контекст/ID и небольшие поля; большие фото не помещаются в состояние экрана.

Контрольные числовые случаи — в acceptance-tests.md; Android-проверки ещё не выполнялись. Реальные записи, снимки, БД и секреты не помещаются в Git.
