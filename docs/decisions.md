# Diet — решения и статус согласования

Обновлено: 15 ноября 2026 года. Этот реестр фиксирует решения; подробные требования находятся в [product-spec.md](product-spec.md), сценарии — в [user-flows.md](user-flows.md). Запись решения не означает реализацию приложения.

| ID | Решение | Основание и статус |
|---|---|---|
| D-001 | Прототип v0.4 принят как база функций, навигации и визуального направления Android-приложения | 15 ноября пользователь сообщил «Прототип меня устраивает» и поручил финальное ТЗ/план. Зафиксирован макет на коммите e60e10e3f41205fac0a6a7f6ddcb18ed21c7ebad. Набор выбранных функций не сокращать молча. |
| D-002 | Сейчас подготовить документацию, код приложения не писать | Явное ограничение текущего запроса. Ни подготовка плана, ни принятие макета не являются разрешением на создание Android-проекта/APK. |
| D-003 | Резервные копии и восстановление исключены | Явное решение 14 ноября. Не добавлять экспорт/импорт/пароль или аккаунт для этой функции. Обычное локальное хранение и сохранение при обновлении обязательны. Системные механизмы Android проверяются как часть приватности, а не новая функция копирования. |
| D-004 | Локальная версия без регистрации и рекламы; интеграции/синхронизация отложены | Прежнее согласованное направление. Отсутствие аккаунта не ограничивает основной дневник. |
| D-005 | Выбран Kotlin + Jetpack Compose + Room; плановая конфигурация зафиксирована отдельно | 15 ноября пользователь явно подтвердил это нативное направление. Версии и поддерживающие компоненты затем выбраны инженерно в D-010; исполнительная проверка TECH-002 ещё не выполнялась. Это отдельное решение после принятия прототипа. |
| D-006 | Рекомендации КБЖУ требуют отдельной верификации | Ручные цели входят в локальную версию. Формула, область применения, активность и распределение БЖУ не выбраны; демонстрационный текст предупреждения не является алгоритмом. ML не требуется. |
| D-007 | Макетные ограничения отделить от требований Android | Фиксированное «сегодня» 14 ноября, временная память, кнопки сбоя/перезапуска и условные данные каталога — инструменты проверки. Они не становятся поведением личного приложения. Лимиты UI, которые принимаются как функциональная база, перечисляются в ТЗ. |
| D-008 | Начат этап 0, только выбор и документация | 15 ноября пользователь попросил помочь выбрать стек/minAndroid и уточнить телефон. Получен частичный профиль телефона; базовый стек и минимум согласованы отдельными ответами. Следующим поручением выбраны плановые версии/SDK и матрица; фактические проверки и некоторые физические сведения ещё открыты. Код по-прежнему запрещён. |
| D-009 | Минимум Android 10+ / API 29 с запасом совместимости | 15 ноября пользователь выбрал этот вариант после сообщения о самом старом Android 14 у близких. Основной телефон — S23+ / Android 17 со слов пользователя; модель близких и остальные физические поля ещё не уточнены. Прежний кандидат Android 8 / API 26 заменён, target/compile SDK выбраны позднее отдельным инженерным решением D-010. Подробности — в [профиле](device-profile.md). |
| D-010 | Плановая конфигурация и Android-матрица выбраны инженерно | 15 ноября пользователь поручил подобрать совместимые версии и выбрать SDK без кода. Выбраны compile/target 37 при min 29; [инструменты](android-build-baseline.md), [библиотеки](android-dependencies.md), [матрица](android-test-matrix.md) — единые источники. Это выполнение поручения, не пользовательское одобрение каждого патча и не результат сборки. Физические поля и исполнительная часть TECH-001/002 ещё открыты. |
| D-011 | Точность и технические пределы определены | По поручению 15 ноября выбран [numeric-contract](numeric-contract.md): micro INTEGER для ввода, точные p/q, HALF_UP при показе, диапазоны/даты/Unicode v1 и защита сложности. Это инженерное решение, не медицинские нормы; эталоны документа проверены, Kotlin/Android ещё не реализован. |
| D-012 | Хранение, миграции и постоянные черновики спроектированы | По тому же поручению выбраны [модель](storage-model.md), [миграции](migrations.md), [черновики](drafts.md): независимые снимки, Room/отдельный DataStore, checkpoint/receipt-first/конфликты и сохранение истории. Физическая schema v1/код/исполнительные тесты остаются будущими; фото/системная доставка/бюджеты не объявлены готовыми. |
| D-013 | Фото: оптимизированная собственная копия, ресурсные бюджеты и файловый протокол | 15 ноября по поручению пользователя инженерно выбраны [обработка](photo-processing.md)/[хранение](media-storage.md): JPEG/sRGB/EXIF, адаптивная память/одна тяжёлая задача, bounded input/output, durable master до refs, all-or-none batch/recovery и GC. Продуктовые 4 фото/5MiB сохранены. Это документальные TECH-005/часть009, не пользовательское одобрение каждого числа и не Android-испытания. |
| D-014 | Личное состояние исключать из управляемых системных backup/transfer | [Политика TECH-006](system-backup-policy.md): CE noBackup и полный inventory, allowBackup=false плюс оба поколения правил/все9 domains, отдельные cloud/D2D/OEM-проверки до первого APK с личными данными. Android config не создаётся; проверка ещё впереди, универсальный контроль OEM/старых копий не обещается. D-003 не меняется, функции экспорта/восстановления нет. |
| D-015 | Разрешена полная Android-реализация по плану | Новое поручение 15 ноября: готовое приложение для телефона, автономные обоснованные улучшения, документирование и отдельные commit/push. Прежний запрет кода D-002 завершает действие для этой фазы. Реальные результаты сборки/испытаний и открытые OEM/физические проверки сообщаются честно; установка/очистка личного телефона автоматически не выполняются. |

Новые инженерные решения должны иметь обозначенный статус: принято пользователем, принято как техническое решение в рамках разрешённой реализации либо предложено к выбору. Нельзя представлять неизбранную формулу, стек или будущую интеграцию как утверждённую часть приложения.

ТЗ v1.0 и план оформляют принятую базу, а [TECH-001–009](technical-decisions.md) отделяют невыбранные инженерные параметры от утверждённых функций. Новая документальная редакция не утверждает сама себе стек/формулу и не разрешает Android-код.
