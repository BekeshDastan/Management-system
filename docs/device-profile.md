Дата: 15 ноября 2026 года. Статус TECH-001: **Android 10+ / API 29 выбран пользователем; профиль получен частично, остальная конфигурация и матрица ещё открыты**. Это документальная часть этапа 0. Выбранное направление стека описано отдельно в [stack-proposal.md](stack-proposal.md), проект/код не создаются.

## 1. Какие сведения нужны

| Оболочка и её версия | Полезно сейчас | One UI/HyperOS/другая, если указана: фон и доставка напоминаний проверяются на реальной системе |
| Физическая ОЗУ и свободное внутреннее место | Полезно, можно позднее | Разделы памяти/обслуживания устройства. Нужны для бюджета фото/тестовых объёмов; виртуальное расширение памяти не принимается за физическую ОЗУ |

| Возможность USB-подключения с передачей данных / предпочтение ручной установки APK | До проверки на телефоне | Выбрать способ установки и сбора результатов. Проверка установки относится к будущему разрешённому этапу разработки |

Достаточный первый ответ: «Модель …, Android …, оболочка …; приложение для …; ОЗУ/свободно …, если известно». IMEI, серийный номер, номер телефона и данные аккаунтов для этого решения не нужны и не фиксируются в репозитории.

## 2. Выбранная нижняя граница

**Принято пользователем 15 ноября: Android 10+ / API 29, то есть minSdk 29.** Самый старый известный целевой Android — 14, поэтому 10–13 оставлены как сознательный запас совместимости. Прежняя предварительная рекомендация Android 8 / API 26 заменена этим выбором. Решение записано в документах; Android-конфигурация пока не создаётся.

| Рассмотренный вариант | Значение для Diet | Статус |
|---|---|---|
| Android 8 / API 26 | Дополнительная поддержка 8–9; среди названных целевых ОС таких нет | Прежнее предложение, не выбрано |
| Android 9 / API 28 | Промежуточный вариант без установленной потребности | Не выбран |
| Android 10 / API 29 | Покрывает названные ОС и оставляет запас 10–13; document-fallback выбора фото всё ещё нужен | Выбран пользователем |
| Android 14 / API 34 | Нижняя известная ОС у близких; уменьшает диапазон поддержки, исключая 10–13 | Рассмотрен, пользователь предпочёл запас |

Конкретные библиотеки должны укладываться в minSdk 29; совместимость всего графа ещё не проверена. Если выбранный артефакт требует более новой ОС, сначала подобрать совместимую версию или пересмотреть компонент. Молча поднимать согласованный минимум нельзя. Более высокий minSdk сам по себе не доказывает ускорение и не гарантирует обновления безопасности телефона.

### minSdk, targetSdk и compileSdk — разные решения

- minSdk — нижняя версия ОС, на которой APK допускает установку.
- targetSdk — уровень поведения Android, под который приложение заявляет адаптацию; не заменяет minSdk.
- compileSdk — доступные при сборке API. Само использование высокого compileSdk не делает новые API доступными на старом телефоне.

Для Diet согласован minSdk 29. Конкретные target/compile и набор проверяемых API выбираются вместе с актуальной стабильной конфигурацией TECH-002; нельзя автоматически поставить 29 во все три поля. Основание: [uses-sdk](https://developer.android.com/guide/topics/manifest/uses-sdk-element) и [настройки SDK при сборке](https://developer.android.com/build).

## 3. Проверенные факты и границы уверенности

- Соответствие Android8/API26 и Android10/API29 — [Android version codes](https://developer.android.com/reference/android/os/Build.VERSION_CODES). Платформенный java.time добавлен на API26: [java.time](https://developer.android.com/reference/java/time/package-summary); notification channels относятся к [Android8](https://developer.android.com/about/versions/oreo/android-8.0).
- Текущая непосредственно открытая [страница AndroidX](https://developer.android.com/jetpack/androidx/versions) указывает default minSdk24 и допускает более высокий минимум отдельных библиотек. В поисковых выдержках встретилось старое23; для записи использован сам первичный документ. Это не универсальный минимум каждого артефакта.
- Generic [Compose quick start](https://developer.android.com/develop/ui/compose/setup) ещё упоминает API21; это не доказательство, что весь современный стек Diet сможет работать на21. Room2.8 имеет собственные release notes о минимуме23; Room3 — отдельная ветка. Проверять конкретные координаты и транзитивные зависимости перед фиксацией конфигурации.
- [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker) может зависеть от доступности системного/backport-модуля; fallback — ACTION_OPEN_DOCUMENT. API29 сам по себе fallback не устраняет. GMS не должен становиться обязательным условием локального дневника. Лимит четырёх фото проверяет Diet и при fallback; фото сохраняется собственной копией.
- Разрешение обычных уведомлений на Android13+ проверяется отдельно. Это не причина требовать Android13 для всего приложения: [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

Источники проверены на дату документа, независимый read-only аудит подтвердил эти различия. Граф будущих артефактов не разрешался, minSdk 29 не проверен сборкой или физическим запуском. Согласованная граница поддержки не является результатом испытаний.

## 4. Предварительная матрица с учётом охвата

| Проверка | Планируемое окружение |
|---|---|
| Нижняя граница | Эмулятор Android 10 / API 29; проверить установку и ключевые сценарии, а не только сборку |
| Повседневный сценарий | Samsung S23+ / Android 17 по сообщению пользователя; перед испытанием записать фактическую ОС/One UI. Проверить offline/restart/клавиатуру/шрифт/память |
| Старое физическое устройство | Телефон близких с Android 14 со слов пользователя; модель ещё нужно уточнить; отдельно проверить повседневные сценарии, фото/графики, расход памяти и напоминания. Эмулятор минимума не доказывает поведение конкретного производителя |
| Адаптация к актуальной платформе | Эмулятор/устройство стабильной версии, выбранной для target/compile; точный номер пока не записан |
| Фото и разрешения | Picker доступен/недоступен, document-fallback, отмена/ошибки, сохранность собственной копии |
| Напоминания и приватность | Применимые границы notification permission, reboot/фон/смена зоны, системное копирование; OEM-поведение на физическом телефоне |

Матрица — план, не выполненные тесты. Показатели S23+ не принимаются за бюджет всех старых устройств: количественные цели TECH-009 задаются с учётом самой слабой выбранной модели, после её уточнения. Физического устройства на Android 10–13 пока не названо; отсутствие таких испытаний отмечать отдельно, эмулятор не выдавать за физическую проверку. В TECH-001 закрыт выбор минимальной ОС, но остаются target/compile, именованная физическая матрица и способ установки. В TECH-002 подтверждено направление Kotlin + Compose + Room, но точные совместимые инструменты/артефакты ещё не закреплены. Оба пункта целиком остаются открытыми. Пользовательское «код пока не пишем» продолжает действовать.
