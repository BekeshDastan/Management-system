# Diet — телефон, минимальный Android и матрица проверки

Дата: 15 ноября 2026 года. Статус TECH-001: **данные телефона запрошены, ответ пока не получен; minSdk не утверждён**. Это документальная часть этапа 0. Стек предложен отдельно в [stack-proposal.md](stack-proposal.md), проект/код не создаются.

## 1. Какие сведения нужны

| Сведения | Приоритет | Где посмотреть / зачем |
|---|---|---|
| Производитель и точная модель | Нужно сейчас | «Настройки → О телефоне». Название и, если видно, код модели нужны для проверки официальных характеристик и физической матрицы |
| Установленная версия Android | Нужно сейчас | «О телефоне → Версия Android» или «Сведения о ПО». Нужна именно текущая установленная версия, не максимальная обещанная обновлением |
| Другие целевые телефоны/самый старый Android | Нужно сейчас | Только этот телефон и будущие устройства либо также близкие/старые модели. Это определяет реальную ценность низкого minSdk |
| Оболочка и её версия | Полезно сейчас | One UI/HyperOS/другая, если указана: фон и доставка напоминаний проверяются на реальной системе |
| Физическая ОЗУ и свободное внутреннее место | Полезно, можно позднее | Разделы памяти/обслуживания устройства. Нужны для бюджета фото/тестовых объёмов; виртуальное расширение памяти не принимается за физическую ОЗУ |
| Google Play services (Сервисы Google Play), магазин Google Play отдельно / нестандартная прошивка | Можно позднее | Не превращать выбор фото в обязательную зависимость от GMS; нужна рабочая системная альтернатива |
| Возможность USB-подключения с передачей данных / предпочтение ручной установки APK | До проверки на телефоне | Выбрать способ установки и сбора результатов. Проверка установки относится к будущему разрешённому этапу разработки |

Достаточный первый ответ: «Модель …, Android …, оболочка …; приложение для …; ОЗУ/свободно …, если известно». IMEI, серийный номер, номер телефона и данные аккаунтов для этого решения не нужны и не фиксируются в репозитории.

### Текущий профиль

| Поле | Состояние |
|---|---|
| Модель / установленный Android / оболочка | Ожидается ответ пользователя |
| Охват устройств | Ожидается ответ пользователя |
| ОЗУ / свободное место / GMS / установка | Не проверены; дополнительных допущений нет |
| Физическая проверка Diet | Не выполнялась, Android-приложение не создано |

По одному названию модели нельзя предположить установленную ОС, объём свободного места или успешность работы Diet. Характеристики, найденные у производителя, будут отделены от фактов пользователя и фактического испытания.

## 2. Предлагаемая нижняя граница

**Предварительно рекомендован Android 8.0+ / API 26.** Это компромисс для Diet: не поддерживать Android 6–7 без выраженной необходимости, сохранить совместимость с 8–9 и использовать платформенные java.time. Рекомендация требует проверки телефона и выбранных артефактов, не является одобрением конкретного dependency graph.

| Вариант | Что означает для проекта | Когда выбирать |
|---|---|---|
| Android 8 / API 26 | Матрица включает8–9; есть платформенные java.time и notification channels, но остаются различия новых разрешений/фоновой работы | Основной предложенный вариант, если полезна совместимость со старыми телефонами |
| Android 9 / API 28 | Исключает8, но сама по себе не упрощает главные сценарии Diet настолько, чтобы выбирать без причины | Если именно Android9 — фактическая нижняя граница целевых устройств |
| Android 10 / API 29 | Исключает8–9 и сужает старую часть матрицы; на10 всё ещё может понадобиться document-fallback выбора фото | Альтернатива, если все целевые устройства≥10 и пользователь предпочитает более узкую поддержку |

Если телефон ниже предложенного минимума, сначала пересмотреть совместимость/ветки библиотек и цену поддержки, а не объявлять аппарат совместимым. Поднятие minSdk не доказывает ускорение и не гарантирует обновления безопасности телефона. Низкий minSdk не означает обязательный старый дизайн.

### minSdk, targetSdk и compileSdk — разные решения

- minSdk — нижняя версия ОС, на которой APK допускает установку.
- targetSdk — уровень поведения Android, под который приложение заявляет адаптацию; не заменяет minSdk.
- compileSdk — доступные при сборке API. Само использование высокого compileSdk не делает новые API доступными на старом телефоне.

Для Diet сейчас предложен только кандидат min26. Конкретные target/compile и набор проверяемых API выбираются вместе с актуальной стабильной конфигурацией TECH-002; нельзя просто поставить26во все три поля. Основание: [uses-sdk](https://developer.android.com/guide/topics/manifest/uses-sdk-element) и [настройки SDK при сборке](https://developer.android.com/build).

## 3. Проверенные факты и границы уверенности

- Соответствие Android8/API26 и Android10/API29 — [Android version codes](https://developer.android.com/reference/android/os/Build.VERSION_CODES). Платформенный java.time добавлен на API26: [java.time](https://developer.android.com/reference/java/time/package-summary); notification channels относятся к [Android8](https://developer.android.com/about/versions/oreo/android-8.0).
- Текущая непосредственно открытая [страница AndroidX](https://developer.android.com/jetpack/androidx/versions) указывает default minSdk24 и допускает более высокий минимум отдельных библиотек. В поисковых выдержках встретилось старое23; для записи использован сам первичный документ. Это не универсальный минимум каждого артефакта.
- Generic [Compose quick start](https://developer.android.com/develop/ui/compose/setup) ещё упоминает API21; это не доказательство, что весь современный стек Diet сможет работать на21. Room2.8 имеет собственные release notes о минимуме23; Room3 — отдельная ветка. Проверять конкретные координаты и транзитивные зависимости перед фиксацией конфигурации.
- [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker) может зависеть от доступности системного/backport-модуля; fallback — ACTION_OPEN_DOCUMENT. API29 сам по себе fallback не устраняет. GMS не должен становиться обязательным условием локального дневника. Лимит четырёх фото проверяет Diet и при fallback; фото сохраняется собственной копией.
- Разрешение обычных уведомлений на Android13+ проверяется отдельно. Это не причина требовать Android13 для всего приложения: [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

Источники проверены на дату документа, независимый read-only аудит подтвердил эти различия. Будущие артефакты не разрешались, min26 не проверен сборкой или физическим запуском; до проверки это рекомендация, а не сертификат совместимости.

## 4. Предварительная матрица после выбора телефона

| Проверка | Планируемое окружение |
|---|---|
| Нижняя граница | Эмулятор выбранного minSdk; если принят26, именноAPI26 |
| Повседневный сценарий | Телефон пользователя с указанными ОС/оболочкой, offline/restart/клавиатура/шрифт/память |
| Адаптация к актуальной платформе | Эмулятор/устройство стабильной версии, выбранной для target/compile; точный номер пока не записан |
| Фото и разрешения | Picker доступен/недоступен, document-fallback, отмена/ошибки, сохранность собственной копии |
| Напоминания и приватность | Применимые границы notification permission, reboot/фон/смена зоны, системное копирование; OEM-поведение на физическом телефоне |

Матрица — план, не выполненные тесты. Решение TECH-001 закрывается после сведений телефона, выбора min/target/compile и именованной матрицы; TECH-002 — после подтверждения направления и фиксации совместимых инструментов/артефактов. Пользовательское «код пока не пишем» продолжает действовать.
