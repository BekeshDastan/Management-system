# Передача проекта Diet

## Задача и этап

Личное Android-приложение для питания, КБЖУ, веса, сна и прогресса. Этап — проектирование продукта и UX. Пользователь поручил полностью завершить прототип; запрос выполнен в сценарном HTML-макете v0.2. Код Android-приложения, APK и база данных не создавались. Общаться на русском.

Папка: D:\Diet. Репозиторий: https://github.com/BekeshDastan/Management-system. Использовалась существующая ветка main, без переписывания истории.

## Принятые границы

- Первая версия — локальный дневник без аккаунта: ручные цели, свои продукты/рецепты, питание, вес, сон, графики, история, темы. Профиль и названия/количество приёмов настраиваются.
- Пользователь исключил резервные копии и восстановление из продукта. Не возвращать их и не проектировать пароль/импорт без нового явного решения.
- Аккаунт, синхронизация и интеграции отложены. Расчётные рекомендации и автоматическая проверка согласованности КБЖУ требуют выбора и проверки правил. Демонстрационный текст предупреждения не является расчётным модулем.
- Игровые названия веса/сна и уровни за заполненные даты приняты как направление. Конкретные названия, пороги и детали UX остаются предложениями. Величины веса, сна и КБЖУ не дают очков; streak не добавлен.
- Kotlin/Compose/Room остаются предложением. Реальные медицинские записи, секреты и ключи в репозитории запрещены.

## Что доступно в v0.2

Все четыре раздела навигации работают. Первый запуск можно пройти без анкеты и целей. В дневнике есть продукты/быстрый ввод/рецепты, исправление по историческому снимку, явная замена и копирование приёма. Справочник поддерживает CRUD, три базы единиц, избранное/недавние. Рецепты сохраняют снимки ингредиентов и отдельный выход блюда.

Профиль редактируется без изменения измерений и целей. Приёмы имеют устойчивые ID, порядок и архив с сохранением истории. История целей показывает даты/периоды и подтверждает изменение прошлого, занятой даты и удаление. Вес/сон, графики, полнота, независимые средние N/Q и игровые настройки сохранены.

Напоминания, разрешение, сбой записи, возврат после закрытия и предупреждение КБЖУ показаны только как явно обозначенные симуляции. Notification API, сеть и постоянный storage не используются. Перезагрузка страницы сбрасывает память; это не проверка NFR-001 на Android.

Для просмотра открыть локальный [index.html](prototype/index.html) и нажать «Полный пример». Подтверждение заменяет только вымышленные данные. Пример содержит профиль, неделю 8–14 ноября, продукты/рецепт и две порции за частичное 7 ноября для списка недавних. Обычный старт остаётся без записей; пример не добавляет скрытые заполненные даты ради уровня.

## Проверки и Git

Каждая часть опубликована отдельно: 3e83c6c — границы; 20cf0f1 — профиль/приёмы; caa62bf — справочник/снимки; a6563b8 — рецепты; 7668162 — правка/копирование; 57e1e90 — цели; b4a510a — ошибки/возврат/полный пример; 5f67f20 — напоминания и завершение маршрутов.

После каждого push проверен remote SHA. Последняя функциональная публикация: `5f67f2032ced414cebdffdc60cd60d952760a141`. Итоговая запись журнала публикуется отдельно; актуальный HEAD проверять по Git, исторический SHA не считать автоматическим указателем.

Независимые целевые наборы и один итоговый E2E прошли; исправлены найденные проблемы единиц, архивного приёма, контекста, подписей и узких заголовков. Отчёт различает широкий светлый сквозной проход и отдельные проверки форм в обеих темах/320 px. JS-ошибок и внешних HTTP-запросов в проверенных маршрутах нет. Реальный Android, TalkBack, хранение и доставка уведомлений не проверялись.

Git add/commit/push выполнялись через штатный require_escalated; защиты, ACL и учётные данные не менялись. В новом чате проверить актуальные status/log/remote и действующие права, сохранить посторонние изменения.
