# Diet — базовая конфигурация Android-сборки

Дата проверки: 15 ноября 2026 года. Статус: **инженерный выбор для будущей реализации по поручению пользователя**, проверенный по официальным таблицам и метаданным. Это документ, а не установленная среда, Gradle-проект или результат сборки. Android-код по-прежнему запрещён.

Пользователь уже выбрал Kotlin + Jetpack Compose + Room и Android 10+ / minSdk 29. Этот документ фиксирует точные инструменты и оставшиеся SDK; поддержка не сужается. Перечень библиотек фиксируется отдельно после проверки их метаданных.

Studio запускается на собственном bundled JBR; STUDIO_JDK не переназначается. JDK Gradle выбирается отдельно. Конкретный компьютер Windows x64 ещё не проверен на пригодность к эмулятору; при другой архитектуре хоста пересмотреть дистрибутив JDK и образы, не менять номера версий молча.

Не применять одновременно built-in Kotlin и org.jetbrains.kotlin.android; не добавлять org.jetbrains.kotlin.jvm в Android app-модуль. Не полагаться на более старый KGP по умолчанию внутри AGP. Повышение runtime KGP выполняется по официальным правилам AGP при будущем создании проекта; сейчас build-файлов нет.

KSP 2.3.14 опубликован 13 ноября; страница overview ещё описывает 2.3.12. Номер KSP не должен совпадать с Kotlin: [изменение схемы версий](https://github.com/google/ksp/releases/tag/2.3.0). Проверку конкретной пары KSP/Room не заменяет наличие релиза.

### Почему не взять последний AGP автоматически

AGP 9.5 существует, но таблица полной поддержки KGP 2.4.21 заканчивается на 9.3.1. Выбрано пересечение опубликованных диапазонов. В 9.3.2/9.3.3 есть дополнительные исправления, включая Lint на JDK 17; JDK 21 обходит именно этот известный путь, но не делает 9.3.1 свободным от других дефектов. Перед первым APK повторно проверить исправления и согласованность патчей, выполнить Lint и проверку minified release. При сбое обновлять проверенный набор отдельным решением, не отключать проверки и не выдавать формальное пересечение таблиц за испытанный инструментальный стек.

Сведения о пакетах прочитаны из [официального каталога SDK](https://dl.google.com/android/repository/repository2-3.xml), без установки. Наличие канала Stable само по себе недостаточно: каталог содержит и пакеты с именем Canary; проверены также имя финальной платформы, пустой codename и релизное объявление.

Android 17 выпущен по [официальному сообщению от 16 июня 2026 года](https://developer.android.com/blog/posts/android-17-is-here); [SDK setup](https://developer.android.com/about/versions/17/setup-sdk) задаёт compile/target 37. Отдельные справочные страницы всё ещё содержат Preview/Beta: для этого решения использованы релизное сообщение и фактические метаданные платформы. Выбор не подтверждает установленную ОС S23+ — её пока сообщил пользователь.

37 выбран как финальная основная платформа нового проекта и для совместимости с выбранными современными AndroidX. Для target 37 обязательна адаптация поведения; Android 10–16 остаются в поддержке. Не заменять minSdk на 37 и не использовать 37.x preview. Правила конкретного магазина проверяются отдельно перед публикацией APK; магазин сейчас не выбран и не является основанием этого решения.

## 3. Границы проверки

Выполнено сейчас:

- сверены официальные таблицы Studio/AGP/Gradle/KGP/JDK и релизы Kotlin/KSP;
- прочитаны Maven/SDK-метаданные без исполнения библиотек;
- зафиксированы конкретные версии и различие между JDK, JVM target и Android SDK.

Не выполнялись установка инструментов, Gradle Sync, разрешение полного транзитивного графа, генерация Room/KSP, Lint, тесты, сборка или запуск APK. Старое наблюдение о PATH/стандартных каталогах не является аудитом всего компьютера. Совместимость по источникам не равна проверенному проекту.

## 4. Первый проверочный шаг после разрешения реализации

До пользовательских записей и функций создать минимальную сборочную основу отдельным малым изменением. Это будущий шаг, не разрешение выполнить его сейчас.

1. Подтвердить архитектуру хоста, выбранный JDK, доступность SDK и аппаратного ускорения. Установки отдельно от текущего документального этапа.
2. Зафиксировать Wrapper с контрольной суммой официального дистрибутива, версии плагинов/библиотек без динамических диапазонов и проверку зависимостей. Отдельно сохранить реально разрешённый граф; не называть список версий lockfile.
3. Проверить версию Gradle/JDK и доступные задачи. Ожидаемые команды будущего проекта: gradlew.bat --version, :app:tasks --all, :app:dependencies --configuration debugRuntimeClasspath. Имена тестовых задач сверить с фактической конфигурацией.
4. Выполнить KSP/Room generation на синтетической пробе, debug-сборку, Lint, предметные unit/instrumentation-проверки и minified release-сборку. Проверить Packaging/native ABI, 4/16 КБ, запуск на API 29 и 37. Сбой не обходить suppressUnsupportedCompileSdk или destructive migration.
5. Записать команды/версии/commit SHA и результаты. Только после этого считать конфигурацию проверенной исполнением; затем переходить к первой пользовательской вертикали плана.

Решение об инструментах принято документально в рамках текущего поручения. Исполнительная часть TECH-002 остаётся открытой; недостающие данные физической матрицы относятся к TECH-001. Отдельное разрешение на Android-код продолжает требоваться.
