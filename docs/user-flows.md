# Diet — пользовательские сценарии

Версия: 0.2 · Дата: 2026-11-14 · Статус: проект сценариев согласованной локальной версии.

Документ описывает поведение будущего приложения. Экраны и приложение ещё не реализованы.
Согласованное направление: личный Android-дневник питания, веса, сна и прогресса с работой офлайн.
Точные поля, тексты, порядок элементов и спорные правила ниже являются предложениями, пока не утверждены отдельно.

Объём первой версии принят пользователем; источник — [раздел 5 ТЗ](product-spec.md#5-согласованные-границы-первой-версии). UX-02 и расчётные режимы UX-03 относятся к последующим этапам. Их отсутствие не блокирует локальный первый запуск.

## Предложенная навигация

| Раздел | Содержание |
|---|---|
| Сегодня | Выбранная дата, прогресс КБЖУ, приёмы пищи, быстрые действия для веса и сна |
| Продукты | Свои продукты, избранное, сохранённые блюда и рецепты |
| Прогресс | История и графики питания, веса и сна; выбор периода |
| Профиль | Личные параметры, цели, тема, напоминания, резервные копии; аккаунт при его появлении |

Утренние, дневные и вечерние подсказки помогают выбрать действие, но не блокируют остальные функции.
Выбранная дата видна во всех формах дневника; переход на прошлый день не меняет текущую календарную дату устройства.

## UX-01. Первый запуск без аккаунта

1. Пользователь начинает локальную работу и создаёт профиль. Для первой версии предлагается одна кнопка «Начать» без экрана входа; UX-02 станет доступен на отдельном этапе.
2. По желанию указывает имя и направление цели: снижение веса, набор массы или поддержание. Анкету можно заполнить позднее в «Профиле»; поля будущей формулы не блокируют ручную настройку.
3. Вводит собственные цели КБЖУ по сценарию UX-03 либо выбирает «Настроить позже» и открывает «Сегодня». Автоматические значения не подставляются до выбора и проверки расчётов.
4. При следующем запуске приложение сразу открывает дневник, сохранив профиль и записи.

- Пустые состояния: у нового пользователя нет еды, веса и графиков; каждый блок предлагает добавить первую запись.
- Ошибки: некорректное значение отмечается рядом с полем; уже введённые данные сохраняются в форме.
- Результат: питание можно записывать без регистрации и интернета.
- Детали ниже — предложение для проверки на прототипе; обязательность полей и пропуск настройки ещё не утверждены пользователем.

### UX-01A. Поля и шаги первого запуска — предложено

| Шаг | Содержимое | Действия и результат |
|---|---|---|
| Приветствие | Короткое объяснение локального дневника без регистрации | «Начать» создаёт один локальный профиль; «Восстановить копию» открывает UX-08 с проверкой файла до изменения данных. Отмена возвращает сюда. |
| Знакомство | Необязательное имя и выбор направления цели; ни одно направление не выбрано заранее | «Продолжить» сохраняет введённое; «Пропустить» продолжает без этих значений. Возраст, рост и исходный вес доступны позднее в профиле, без обязательного заполнения при старте. |
| Ручные цели | Калории в ккал, белки/жиры/углеводы в граммах; пустые поля с подписями единиц | «Сохранить и начать» доступно для полного допустимого набора; «Настроить позже» начинает дневник без активной цели. Цели не берутся из примеров или заполнителей полей. |
| Дневник | Текущая дата, еда, вес и сон; состояние каждой записи отдельно | При отсутствии цели показывать «Цель не задана» и «Настроить цель». Доступны добавление еды, веса, сна и просмотр истории. |

- Имя используется только для отображения. Пробелы по краям убираются; пустое имя не заменяется выдуманным. Направление цели само по себе не меняет КБЖУ.
- Возраст, рост и вес в профиле не создают записи измерений автоматически. Запись утреннего веса выполняется явно через UX-05 с выбранной датой.
- Для ручной цели предлагаются четыре обязательных числовых поля: калории больше нуля, каждое БЖУ неотрицательно. Принимаются десятичные запятая и точка; пустое значение не равно нулю. Это техническая проверка ввода, а не оценка пригодности цели; пределы, точность и правило предупреждения о расхождении остаются открытыми в UX-03.
- При «Настроить позже» частично введённые цели остаются черновиком и не используются в дневнике или аналитике. При следующем открытии настройки можно продолжить ввод либо явно очистить черновик.
- Без цели видны записанные КБЖУ, но нет процентов выполнения, «остатка», превышения или оценки достижения цели. Отсутствие еды по-прежнему обозначается «Нет записей». Отсутствие цели и отсутствие записей — разные состояния.
- Перед сохранением первой цели видна дата начала действия, по умолчанию сегодня. Если во время настройки наступил новый день, дата обновляется с заметным пояснением и требует повторного подтверждения. Цель не заполняет прошлые дни автоматически.

### UX-01B. Возврат и прерывание — предложено

- Кнопка «Назад» возвращает на предыдущий шаг и сохраняет черновик; она не удаляет уже записанные данные.
- После завершения редактирования поля и перед переходом между шагами черновик сохраняется локально. После закрытия процесса открывается последний сохранённый шаг с последними сохранёнными полями; несохранённые символы во время ввода не обещаются восстановленными.
- Черновик отделён от активного профиля и целей. Недопустимое значение можно восстановить в поле с ошибкой, но нельзя применить как цель. Ошибка сохранения оставляет пользователя на шаге с введёнными значениями и действием «Повторить»; успешный переход не показывается.
- Завершение настройки и применение цели выполняются как одно целое. Повторное нажатие или перезапуск после успеха не создают второй профиль и вторую цель; открывается дневник. При «Настроить позже» завершение первого запуска сохраняется без активной цели.
- Успешное восстановление копии открывает восстановленный дневник, без повторной обязательной анкеты; при отсутствии целей действует состояние «Цель не задана». Ошибка или отмена восстановления сохраняет прежнее состояние первого запуска.
- Первый запуск не запрашивает разрешение на уведомления: напоминания рассматриваются на своём этапе. Выбор системного файла для восстановления доступен только после соответствующего действия пользователя.

## UX-02. Необязательный аккаунт

1. Когда функция будет реализована, пользователь сможет выбрать вход при первом запуске или позже в «Профиле».
2. Перед подключением приложение объясняет, какие данные будут синхронизироваться; уже созданный локальный дневник сохраняется.
3. Успешный вход возвращает к дневнику. Ошибка входа не закрывает доступ к локальным функциям.

- Пустые состояния и ошибки: нет сети, вход отменён, аккаунт содержит другую историю — понятное сообщение без потери локальных записей.
- Результат: наличие аккаунта не становится условием ведения дневника офлайн.
- Согласовано: аккаунты и синхронизация отложены за пределы первой локальной версии.
- Открыто для будущего этапа: способ входа, хранение в облаке и правила разрешения конфликтов. Слияние данных не считается спроектированным.

## UX-03. Настройка и изменение КБЖУ

1. В первой версии пользователь вводит калорийность и БЖУ полностью вручную. Переключатель расчётных режимов предлагается показывать после их появления.
2. На следующем этапе, после проверки формул, добавляются рекомендация по алгоритму и своя калорийность с предложенным БЖУ. Для рекомендации пользователь вводит параметры утверждённой формулы, включая уровень активности; видит результат и объяснение расчёта.
3. При ручном вводе видит предупреждение о несогласованности калорий и БЖУ, если она обнаружена; значения не меняются скрытно.
4. Проверяет дату начала действия цели и сохраняет её. Главная показывает цель для выбранного дня.

- Предложено: настройку можно отложить по UX-01A. Отсутствующая цель не равна нулевой; до её сохранения сравнения с целью не строятся. Черновик не влияет на действующую цель при её последующем редактировании.

- Ошибки: пустые обязательные поля, нечисловые значения, неподдерживаемые параметры — объяснение и сохранение введённых данных.
- Результат: новая цель не переписывает прежние цели и сравнения в истории.
- Открыто: формула, диапазоны допустимых параметров, точность округления, правила предупреждений и изменения цели задним числом.

## UX-04. Запись еды

1. В выбранном дне пользователь нажимает «Добавить» у приёма пищи.
2. Выбирает продукт или блюдо из поиска, недавних или избранного; при отсутствии создаёт продукт с данными с упаковки.
3. Указывает количество и единицу. До сохранения видит рассчитанные КБЖУ порции.
4. Сохраняет запись: она появляется в приёме пищи, а дневные итоги и полоски обновляются.

- Дополнительные согласованные способы: копирование приёма пищи и быстрый ввод КБЖУ без создания продукта.
- Для домашнего рецепта предусматриваются ингредиенты и итоговый вес готового блюда; запись порции хранит значения на момент добавления.
- Пустое состояние: поиск без результатов предлагает создание своего продукта, не выдумывая пищевую ценность.
- Ошибки: недопустимое количество или единица выделяются в форме; повторное нажатие сохранения не создаёт дубликат.
- Результат: изменение карточки продукта впоследствии не меняет уже записанные приёмы пищи.
- Открыто: набор единиц, формат ввода порций и редактирования рецепта; сканирование штрихкодов и фото еды не включены в этот сценарий.

## UX-05. Утреннее взвешивание и сон

1. На главной пользователь выбирает «Записать вес», проверяет дату и единицу, вводит значение и сохраняет.
2. В блоке сна вводит длительность. Предлагаемая дополнительная форма — время засыпания и пробуждения с датами.
3. Сон через полночь считается по полным датам и времени; перед сохранением отображается длительность.
4. Пользователь может внести данные позже, выбрав соответствующую дату, или пропустить действие.

- Пустые состояния: отсутствующий вес или сон обозначается как «Нет записи», а не как ноль.
- Ошибки: неправильные числа, отрицательная длительность, некорректная последовательность времени — сообщение до сохранения.
- Результат: показатели доступны в истории после перезапуска; пропуск не вызывает обвиняющих сообщений.
- Открыто: одна или несколько записей веса за день, дневной сон, допустимые диапазоны длительности.
- Предложение для согласования: ночной сон относится к локальной дате пробуждения; переходы часового пояса требуют отдельного правила.

## UX-06. Исправление прошлых записей

1. Через выбор даты пользователь открывает нужный день и выбирает запись.
2. Меняет количество, значение или время; проверяет итог и сохраняет. Удаление предусматривает подтверждение либо возможность отмены.
3. Приложение пересчитывает относящиеся к записи итоги и графики; остальные дни не меняются.

- Ошибки: отмена формы оставляет исходную запись; неудачное сохранение явно показано и не создаёт видимость успеха.
- Результат: корректировка одной записи не заменяет справочник продуктов и не меняет другие исторические записи.
- Открыто: способ отмены удаления и статус «День заполнен» после последующего редактирования.

## UX-07. Завершение дня и просмотр прогресса

1. Пользователь проверяет приёмы пищи и выбирает «День заполнен», подтверждая полноту записей.
2. Главная различает день без записей, частично записанный и заполненный; превышение цели показывается числом, не скрывается пределом шкалы.
3. В «Прогрессе» пользователь выбирает неделю, месяц, год или произвольный период и показатель.
4. Видит измерения веса и недельное среднее, калории относительно исторической цели, БЖУ и длительность сна.

- Пустые состояния: при недостатке данных показываются доступные точки и пояснение; отсутствие записей не изображается нулевым потреблением.
- Для средних явно указывается, какие дни вошли в расчёт; неполные дни не считаются полными автоматически.
- Результат: изменение периода и фильтров не меняет исходные записи. Графики не делают причинных выводов о влиянии сна или еды.
- Предложение: streak за заполнение дневника и регулярность за неделю, без наград за низкую калорийность или скорость снижения веса.
- Открыто: точные правила streak, включения неполных дней в статистику и вычисления недельного среднего.

## UX-08. Резервная копия и восстановление

1. В «Профиле» пользователь выбирает экспорт, указывает место сохранения и получает подтверждение только после успешной записи файла.
2. Для восстановления выбирает файл. Приложение сначала проверяет формат, версию и целостность без изменения текущих данных.
3. Показывает доступное описание копии и последствия восстановления; замену имеющихся данных пользователь подтверждает явно.
4. После успеха дневник, справочник, история целей и настройки соответствуют восстановленной копии в согласованном объёме.

- Ошибки: повреждённый файл, неподдерживаемая версия, нехватка места или отмена выбора — сообщение; текущий дневник сохраняется.
- Результат: экспорт и восстановление работают без аккаунта; проверка включает перенос между двумя установками приложения.
- Открыто: формат и защита копии, точный состав, обработка будущих вложений; предлагаемый первый режим — полная замена, не слияние.

## Следующая проверка сценариев

- Объём первой локальной версии согласован. Для первого запуска подготовлены предложения UX-01A/B; проверить их на прототипе. Следом уточнить единицы еды и правила полноты дня, затем подготовить прототип первого запуска, главной и добавления еды.
- Проверить крупный системный шрифт, обе темы, клавиатуру, небольшой экран, отмену действия и отсутствие сети.
- Обновлять этот документ при изменении поведения; отмечать причину и результат проверки в журнале проекта.
