# Diet — матрица будущих Android-проверок

Дата: 15 ноября 2026 года. **Статус: planned / not run.** Это документальная часть этапа 0; Android-проект, APK и эмуляторы для Diet не созданы, проверки ниже не запускались.

## 1. База и границы

- Выбраны `minSdk 29`, `targetSdk 37`, `compileSdk 37`; Android SDK Platform 37.0 — финальный пакет, не preview. Выбор базы не доказывает успешную сборку или совместимость транзитивных зависимостей.
- Основания SDK: [релиз Android 17](https://android-developers.googleblog.com/2026/06/Android-17.html), [официальный SDK setup](https://developer.android.com/about/versions/17/setup-sdk), [Google SDK repository](https://dl.google.com/android/repository/repository2-3.xml). В repository проверен `platforms;android-37.0`, revision 2, channel-0, без codename.
- План учитывает выбранный `BundledSQLiteDriver` / `sqlite-bundled 2.7.1`: это зависимость с native-компонентом; надписи «Kotlin» недостаточно для вывода об отсутствии `.so`. [AndroidX SQLite](https://developer.android.com/jetpack/androidx/releases/sqlite).
- Выбранные версии инструментов — [базовая конфигурация](android-build-baseline.md), библиотек — [каталог зависимостей](android-dependencies.md).
- Требования/ожидаемые результаты: [ТЗ](product-spec.md), [правила данных](data-rules.md), [приёмочные случаи](acceptance-tests.md), [технические ворота](technical-decisions.md), [профиль устройств](device-profile.md), [план этапов](development-plan.md).
- Все данные/изображения синтетические. Проверки исключения backup не возвращают экспорт/импорт в продукт. Браузерные 320 px не считаются Android 320 dp.

## 2. Минимальные окружения

Один и тот же проверяемый APK с target 37 устанавливается на разные runtime API. До запуска фиксируются пакет/ревизия system image, ABI, page size, вариант GMS и фактическая доступность picker; наличие API само по себе не доказывает наличие обновляемого picker-модуля.

| Строка окружения | Профиль и предметная граница | Дополнительные проверки к smoke | Статус |
|---|---|---|---|
| E29 — Android 10 / API 29 | Нижняя граница; AOSP/без GMS с недоступным Photo Picker | Document-fallback, собственная копия/отмена/лимит фото: CV-009–012; legacy backup-конфигурация AN-007; установка и загрузка native-драйвера | planned / not run |
| E31 — Android 12 / API 31 | Граница `dataExtractionRules`, cloud и D2D; до notification runtime permission | AN-007 отдельными transport-проверками; CV-009/010 при фактически доступном модульном picker; CV-019/020 без ложного запроса разрешения API 33 | planned / not run |
| E33 — Android 13 / API 33 | Первая граница `POST_NOTIFICATIONS` | CV-019/020: allow/deny/закрытие диалога/отзыв; состояния после разрешённых/запрещённых уведомлений на прежней ОС; AN-001 | planned / not run |
| E34 — Android 14 / API 34 | Известная ОС близких; фото и изменение доступа к источнику | CV-009–014, отсутствие ненужного доступа ко всей галерее, AN-002/003; эмулятор не заменяет неизвестную физическую модель | planned / not run |
| E35 — Android 15 / API 35, обычный образ | Edge-to-edge при современном target | AN-005, PG-013, CV-018: вырез/системные панели/IME/жесты/три кнопки, формы и нижняя навигация | planned / not run |
| E36 — Android 16 / API 36 | При target 37 нельзя полагаться на прежний opt-out edge-to-edge | AN-005/002, CV-014/018: Back, отмена грязного черновика, возврат к фильтрам/разделам, системные отступы | planned / not run |
| E37 — Android 17 / API 37 | Целевая платформа; обычный телефонный профиль и отдельный большой/изменяемый профиль | Весь применимый каталог; AN-002/005 и CV-018/PG-013 при вращении/resize и изменении окна | planned / not run |
| N16 — Android 15 / API 35, отдельный 16 KB image | Не обычный E35: фактическая страница памяти 16384 байта | Native-проверки раздела 5, AN-001/003/004 по готовым схемам, AN-008; установка/открытие/запись/повторное открытие БД | planned / not run |

API 30/32 не добавляются автоматически: legacy backup покрыт E29, модульный picker/pre-33 — E31. Если выбранная интеграция включает backport picker на API 29, добавить вариант E29 с установленным модулем; обязательный fallback без GMS сохраняется. Если ветвь не достигается в принятой конфигурации, записать причину неприменимости, а не заявлять её PASS.

Для E37 использовать small-профиль `sw < 600 dp` и large-профиль `sw > 600 dp`, проверить также границу 600 dp; затем уменьшать/увеличивать окно, поворачивать и открывать клавиатуру. На large-профиле проверяется адаптация существующих экранов/сохранность черновиков; новый планшетный продукт, отдельная навигация или tablet-only функции не добавляются. При target 37 запрет resize/ориентации не служит исправлением. [Официальное изменение Android 17](https://developer.android.com/about/versions/17/changes/ff-restrictions-ignored).

## 3. Распределение нагрузки: ядро и полный релиз

Не требуется прогонять весь каталог на каждом API после каждой правки. Применимость определяется готовой функцией; случай будущего этапа помечается «не реализовано в контрольном ядре», а не PASS.

| Срез | Где и что запускать после появления APK |
|---|---|
| Числовое ядро | Синтетические FD/DY/WT/SL/GM/PG в независимых проверках правил после изменения логики; не повторять всю арифметику вручную на каждом AVD |
| Smoke ядра на E29–E37 | AC-001–003, ON-001, WT-001, SL-001, PG-001–004, CV-018, применимые AN-001/006: старт/факт/снимок/измерения/сводка/restart/офлайн |
| Полная проверка контрольного ядра | E29 и E37: применимые AC/ON/FD/DY/WT/SL/PG, CV-001/018/021–023/025 и AN-001–009/011 по составу этапов 1–6; GM/остальные CV ещё не объявлять выполненными |
| Smoke полного состава на E29–E37 | AN-010 как связный маршрут всех функций, плюс restart/offline AN-001/006; предметные границы — по строкам окружений выше |
| Полная синтетическая приёмка v0.4 | E29 и E37: весь применимый каталог, включая GM, CV-001–025 и AN; на физических устройствах — полный пользовательский маршрут и применимые UI/системные/OEM-проверки |
| Каждый профиль N16 | Предметный DB/native-набор, не весь повтор пользовательского каталога; повтор при изменении драйвера, ABI, упаковки, AGP/NDK или native-зависимости |

В ядре AN-008 выполняется для готовых функций с выбранными порогами TECH-009; неготовые фото/лента не считаются проверенными. Полный AN-010 отмечается только в полном составе. AN-004 требует сохранённого набора предыдущей схемы/версии, а не разрушительного пересоздания БД.

## 5. Native SQLite: ABI и 16 KB

1. В будущем APK составить список реально упакованных `.so` и ABI, включая bundled SQLite; проверить наличие библиотек для выбранных физических и эмуляторных ABI. Нельзя объявить поддержку ABI только по имени зависимости.
2. Проверить ELF LOAD/RELRO и упаковочное выравнивание по официальной инструкции; успешная проверка ZIP не заменяет ELF-проверку. Сохранить версии инструментов и отчёт для проверяемого APK/SHA.
3. Отдельно использовать Google APIs Experimental 16 KB Page Size ARM64 либо x86_64 image API 35 по доступной архитектуре хоста; точный package/revision занести в отчёт. Не подменять его обычным 4 KB образом с похожим названием.
4. Будущие диагностические команды: `adb shell getconf PAGE_SIZE` должно показать `16384`; `zipalign -c -P 16 4 <APK>` проверяет упаковку. ELF проверяется APK Analyzer или инструментами NDK. Сейчас команды не выполняются.
5. PASS: установка/запуск, чтение/запись/транзакция/перезапуск и доступная миграция проходят без linker/SQLite-сбоя; native-совместимость подтверждена без маскировки режимом 16 KB backcompat. При проблеме исправляется зависимость/упаковка, а не молча повышается minSdk.

Основание и точные способы проверок: [Android: поддержка 16 KB](https://developer.android.com/guide/practices/page-sizes). Эти проверки относятся к TECH-002/004/009 и существующим AN-001/003/004/008; новых приёмочных ID здесь не назначается.

## 6. Разные виды обновления и переноса

| Операция | Что сохранять/проверять | Граница результата |
|---|---|---|
| APK update на той же ОС | Установить следующую подписанную версию поверх предыдущей без uninstall; AN-004/001/003, все виды записей/снимков/фото/настроек | Не доказывает работу после обновления ОС |
| OS upgrade с тем же APK | На поддерживаемом тестовом устройстве реальное официальное обновление; AN-001/011, CV-009/019/020 и контекст/локальные фото | Смена AVD и перенос snapshot не являются OTA; без подходящей пары ОС/обновления — blocked |
| Повышение target SDK | При будущем изменении baseline сравнить поведение на одной runtime-ОС, отдельно от миграции схемы; AN-005/006, CV-009/019/020 и актуальные platform changes | Baseline сейчас 37; не нужен искусственный «старый релиз Diet», которого нет. Compat toggles — диагностика, не замена итоговой сборки |
| Cloud backup/restore — исключение | AN-007: синтетические БД/фото/настройки/черновики не возвращаются после системного восстановления | Проверяется отсутствие переноса данных, не добавляется функция резервных копий |
| D2D transfer — исключение | AN-007 отдельно от cloud, включая OEM-путь; личное состояние Diet не появляется на приёмнике | Установка пустого APK допустима; нельзя обещать управление непроверенным OEM. Нет транспорта/устройства — blocked |

Для границы разрешений API 33 использовать официальные состояния allow/deny и upgrade pre-grant/сохранённого запрета; ADB-симуляция состояния разрешения не объявляется полной проверкой OS upgrade. [Notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

Backup проверяется двумя поколениями правил: на API ≤30 — legacy, на API ≥31 при target 37 — `dataExtractionRules` с независимыми cloud/D2D-исключениями. Один `allowBackup=false` не считается доказательством контроля OEM-переноса. [Auto Backup](https://developer.android.com/identity/data/autobackup), [тестирование транспорта](https://developer.android.com/identity/data/testingbackup).

## 7. Статусы, доказательства и ворота выпуска

- `planned / not run`: случай назначен окружению, но ещё не запускался; это статус назначенных тестов сейчас; сведения о физических устройствах отдельно помечены pending.
- `blocked`: запуск невозможен из-за отсутствия APK/устройства/образа/транспорта/утверждённого допуска TECH-007 или бюджета TECH-009; назвать конкретную причину.
- `PASS`: записаны APK SHA/commit, конфигурация SDK, ABI/page size, ОС/образ/устройство, шаги/ожидаемое/фактическое и доступные обезличенные доказательства; применимые критерии выполнены.
- `FAIL`: наблюдается расхождение, потеря/подмена данных, неверная доступность или доставка; не переименовывать дефект в «не проверено».
- `N/A`: неприменимость обоснована составом текущего среза; не означает готовность ещё не реализованной функции полного релиза. В полном v0.4 обязательную функцию нельзя скрыть этой отметкой только потому, что её не успели реализовать.

Перед первым APK с пользовательскими данными закрывается TECH-006 для согласованной матрицы. Если выбранный OEM всё же переносит исключённые данные, AN-007 не получает PASS «с оговоркой»: зафиксировать дефект/ограничение и решить допустимость выпуска на этом устройстве.

Документально сейчас фиксируются baseline 29/37/37, окружения, распределение случаев и недостающие сведения. Разрешение графа зависимостей, сборка/установка, native alignment, доставка, миграции и физическая совместимость остаются до будущих запусков. Неизвестные ответы по устройствам не блокируют подготовку плана и не заменяются выдуманными характеристиками.

## 8. Первичные основания границ

- [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker): доступность модулей, document-fallback и предел выбора; Diet проверяет собственный лимит и сохраняет независимую копию.
- [Android 14: частичный доступ к фото](https://developer.android.com/about/versions/14/changes/partial-photo-video-access): не вводить собственную галерею с широкими разрешениями ради обычного выбора.
- [Android 15: изменения UI](https://developer.android.com/about/versions/15/behavior-changes-15) и [Android 16: edge-to-edge/Back](https://developer.android.com/about/versions/16/behavior-changes-16): предметные E35/E36 вместо вывода по одному новому телефону.
- [Android 17: resize/ориентация](https://developer.android.com/about/versions/17/changes/ff-restrictions-ignored): large-профиль проверяет обязательную адаптацию существующего продукта, а не расширяет его функции.
- [Compatibility framework](https://developer.android.com/guide/app-compatibility/test-debug): помогает изолировать изменения поведения; окончательная приёмка проводится с выбранным target и обычными системными настройками.
