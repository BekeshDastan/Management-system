# Diet — выбранный стек и организация приложения

Дата: 15 ноября 2026 года. Статус: **пользователь выбрал Kotlin + Jetpack Compose + Room 15 ноября; плановые версии инструментов/библиотек теперь выбраны инженерно, сборка не проверена**. Выбран и минимум Android 10+ / API 29. Документальный этап 0 продолжается, код приложения по-прежнему не пишется. Точные версии/SDK находятся в [базовой конфигурации](android-build-baseline.md) и [каталоге библиотек](android-dependencies.md), проверки — в [матрице](android-test-matrix.md). Открыты исполнительная проверка TECH-002 и недостающие физические сведения TECH-001.

## 1. Принятый базовый стек

**Принято пользователем: нативное Android-приложение на Kotlin + Jetpack Compose + Room.** Это выбор для Android-only/offline объёма Diet. В рамках следующего поручения подобрать библиотеки инженерно выбраны Material 3, ViewModel/Coroutines/Flow, DataStore, Navigation 3 и Room 2 с bundled SQLite. Их точные версии фиксируются в каталоге; это не отдельное пользовательское одобрение каждой версии и не готовый проект. Системный выбор фото и собственная локальная копия должны выполнять уже принятый контракт данных.

| Часть | Выбранная плановая основа | Зачем Diet |
|---|---|---|
| Язык | Kotlin — принято | Один основной язык для Android UI, данных и проверяемых правил |
| Интерфейс | Jetpack Compose — принято; Material 3 с собственными цветами/компонентами макета — инженерный выбор | Темы, карточки, раскрываемые отчёты, анимации и доступность; Material не заменяет согласованный дизайн стандартным шаблоном |
| Состояние экранов | ViewModel, StateFlow, Coroutines и lifecycle-aware подписки | Отдельные черновики/ошибки, восстановление контекста, фоновые операции без блокировки интерфейса |
| История | Room 2 + BundledSQLiteDriver, версии по каталогу | Связанные записи, снимки, цели по датам, поиск, миграции и транзакции |
| Настройки | DataStore для независимых визуальных предпочтений | Тема/акцент/порядок блоков. Данные, которые должны изменяться одной транзакцией с фактами, остаются в Room |
| Вычисления | Отдельные проверяемые Kotlin-правила без зависимости от UI/БД | Порции/рецепты, округление, N/Q и уровни; числовые типы/границы выбираются в TECH-003 |
| Фото | Системный Photo Picker с document-fallback и постоянной копией в области приложения | Локальные фото и лента после перезапуска, без обязательного доступа ко всей галерее |
| Навигация/графики | Navigation 3 для Compose; доступные графики с отдельными расчётами/текстовыми значениями | Navigation 3 зафиксирован в каталоге; внешняя библиотека графиков не выбрана, возможны средства Compose и доступные текстовые значения |
| Напоминания | Android-уведомления и выбранный позже локальный планировщик | Не назначать WorkManager/точные alarms автоматически: условия доставки закрываются в TECH-007 |

Предлагаемая организация — понятные UI, правила и слой данных с репозиториями. Не требуется заранее создавать много Gradle-модулей. Навигация, DI, загрузка изображений и графики не должны добавлять ненужные зависимости до проверки их роли и совместимости.

### Границы хранения

DataStore не становится хранилищем дневника/снимков/планов. Профиль, факт, цель, полнота и история переносов, которые требуют согласованной записи, проектируются в одной подходящей транзакционной границе. Малое состояние экрана не заменяет постоянное хранение; фото не помещается в ViewModel/Bundle как большая картинка. Это сохраняет NFR-001/002/007.

### Почему этот вариант

Текущая цель — одно Android-приложение с тесной связью с жизненным циклом, локальными данными, выбором фото и уведомлениями. Нативный стек прямо соответствует этому составу; это инженерная оценка по ТЗ. Flutter/React Native стоит пересматривать при отдельном решении о второй платформе. Оборачивание HTML-макета само по себе не выполняет Android-контракт хранения/миграций/фото/напоминаний.

## 2. Что проверено по первичным источникам

- Android рекомендует ViewModel, Coroutines/Flow и разделение UI/данных: [architecture recommendations](https://developer.android.com/topic/architecture/recommendations). Для Diet расчётный слой выделяется из-за правил истории и аналитики.
- Room предназначен для локальных структурированных данных: [руководство Room](https://developer.android.com/training/data-storage/room). DataStore подходит для небольших наборов настроек, а связанные/сложные данные требуют другого инструмента: [DataStore](https://developer.android.com/topic/libraries/architecture/datastore).
- Compose BOM согласует версии Compose-библиотек, но не является полной фиксацией всего Android/Kotlin/toolchain: [BOM](https://developer.android.com/develop/ui/compose/bom). Для Kotlin 2+ compiler plugin имеет собственную связь с версией Kotlin.
- Одновременно опубликованы ветки [Room 2.x](https://developer.android.com/jetpack/androidx/releases/room) и [Room 3.x](https://developer.android.com/jetpack/androidx/releases/room3). На дату чтения страницы показывают stable 2.8.5 и 3.0.3 соответственно. Room 3 использует другие координаты/пакет и KSP; нельзя смешивать примеры разных веток. Для Diet выбрана Room 2.8.5; причины и драйвер приведены в каталоге, Room 3 не смешивается с её координатами.
- Совместимые Android Studio/AGP/Gradle выбираются по [таблице AGP](https://developer.android.com/build/releases/about-agp) и [релизам Studio](https://developer.android.com/studio/releases), а не независимым выбором «последнего» каждого инструмента.

Плановые версии Kotlin/Compose/Material/Room/SQLite/KSP/Activity/Lifecycle/DataStore/Navigation/инструментов/SDK теперь закреплены в отдельных документах. Прочитаны BOM/POM и девять AAR; это не lockfile и не полный граф. Разрешение графа, генерация KSP и сборка — первый будущий шаг после разрешения кода, до функционального этапа 1.

Проверено только чтением, без установки и конфигурации:

- adb, sdkmanager и gradle не найдены в текущем PATH;
- стандартные каталоги Android Studio в Program Files и SDK в пользовательском AppData/Local/Android не найдены;
- команда java найдена в PATH, но версия JDK этим сеансом не подтверждена: запуск запроса версии не завершился и был прерван.

Это не полный поиск установок по компьютеру и не доказательство отсутствия инструментов в другом месте. Среда сборки пока не считается проверенной. Установки, Gradle-wrapper, Android-проект, зависимости и APK не создавались.
