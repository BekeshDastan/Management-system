# Diet — виджет рабочего стола

Согласовано пользователем в UX-обновлении1.1: виджет с текущим питанием и быстрым добавлением. Реализация: platform RemoteViews, без новых библиотек, сетевых вызовов или разрешений; поддержка minSdk29.

## Поведение

- На рабочем столе: точная дата, записанные калории за эту дату, действующая ручная цель, состояние заполненности; кнопки «Еда», «Вес», «Сон» и обновление. Фото, имя профиля и значения веса/сна на рабочий стол не выводятся.
- Пустой пропуск показывает «— ккал»; отдельно подтверждённое отсутствие еды — «0,0 ккал» и пояснение. Неполный день явно подписан. Суммы используют тот же точный ReportDay и HALF_UP как приложение, не первые40строк текущей вкладки.
- Нажатие быстрого действия открывает соответствующую форму на текущую местную дату в момент нажатия. Старый PendingIntent не несёт дату старой записи. Незавершённый редактор проходит существующий механизм сохранения черновика; виджет сам ничего не записывает.
- Чтение виджета не меняет выбранную дату дневника. Есть0данных виджета в SharedPreferences/новом файле: он читает CE Room и передаёт ограниченный набор текста системному launcher.
- После подтверждённой записи обновление вызывает Room invalidation. Дополнительно: возврат в приложение, изменение размера виджета, boot/time/timezone/date/package события, штатное периодическое обновление30мин и неточный non-wakeup alarm на следующую местную полночь. Если процесс убит/ОС задерживает обновление, явная дата остаётся возле чисел; вчерашние числа не подписываются «сегодня». Нажатие ↻ перечитывает данные.
- Время обновления в Doze/OEM не гарантировано. ExactAlarm/foreground service/исключение экономии батареи не используются. Источник официально описывает ограничение периодического обновления: [Android Widgets advanced](https://developer.android.com/develop/ui/views/appwidgets/advanced).
- Метаданные ограниченыhome_screen; API36+ добавляетnot_keyguard. Дополнительно runtime hostCategorykeyguard получает заглушку без калорий/целей. not_keyguard обязателен к учёту самим host; [официальное описание](https://developer.android.com/reference/android/appwidget/AppWidgetProviderInfo#WIDGET_CATEGORY_NOT_KEYGUARD). Не заявляется проверенная гарантия для неизвестного OEM.
- Receiver приватный/directBootfalse, background work ограничен timeout7с с goAsync/finallyfinish и существующим wakepermission/lock9с. Чтение summary ограничено5с. При ошибке вместо оставшегося ложного «свежего» результата показывается просьба обновить; SQL/пути/личные данные в текст ошибки не попадают.

## Как добавить

Удержать свободное место рабочего стола → «Виджеты» → Diet → выбрать виджет. В совместимых launcher можно использовать кнопку добавления из настроек Diet и подтвердить размещение в системном окне. По умолчанию4×3ячейки наAPI31+, минимум250×230dp; разрешено увеличить размеры. Точное количество ячеек определяет launcher. [Размеры Android widgets](https://developer.android.com/develop/ui/views/appwidgets/layouts).

## Проверки

Добавлены4JVMслучая: пропуск/явныйноль, partial/complete и точное округление, дата/цель, полночь в23/25часовых днях. Добавлены2Androidслучая: реальный ReportDay при выбранной прошлой дате/цели/полноте; RemoteViews/native inflation/48dp action targets/доступные descriptions/metadata/immutable разные intents. Запуск и результат фиксирует координатор в build-validation; наличие теста само не являетсяPASS. Физический SamsungLauncher, поведение OEMlockscreen/Doze и долгие обновления после полуночи требуют отдельной проверки.
